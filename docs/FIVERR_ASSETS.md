# Fiverr Gig Assets — Planning

No images are generated by this document — Fiverr Gig images should be
made deliberately (a design tool, a screenshot, a simple template), not
auto-generated placeholders. This is a composition brief for three images,
plus rules for what must never appear in any of them.

## Hard rules for every image

Never include, in any screenshot or composition:
- API keys, tokens, or any credential value
- The contents of a `.env` file
- A terminal/console showing internal paths, personal usernames, or
  sensitive log output (e.g. `C:\Users\<name>\...`)
- Any real personal data

Crop or blur first if a real screenshot happens to include any of the
above — never publish it "as is" and fix it later.

## Image 1 — Gig Cover

**Purpose:** the first thing a buyer sees in search results.

**Suggested composition:** dark background, minimal, on-brand with the
dashboard's own dark/purple identity (`frontend/src/styles/tokens.css`).

**Suggested text:**
```
CUSTOM REST API DEVELOPMENT
Node.js • Express • API Integrations
```

**Notes:** keep it text-forward and simple — Gig cover images are usually
viewed small in search results, so a busy screenshot won't read well here.
A clean typographic composition (no live app screenshot) works better for
this slot specifically.

## Image 2 — Case Study

**Purpose:** show that the portfolio claim is backed by a real, working
project.

**Suggested composition:** a **real screenshot** of the running dashboard
— ideally the success state showing the map, competition-indicator ring and
metric cards after a completed analysis (mock mode is fine and honest to
show, since the "Mock Mode" badge is visible and explains itself).

**Suggested caption/overlay text:**
```
Business Location Intelligence API
Geospatial analysis · REST API · React dashboard
```

**Notes:** this is the one slot where a real product screenshot belongs.
Take it after starting both the backend (mock mode, no cost) and the
frontend locally, running a real analysis (see the README's Installation
section), and cropping out the browser chrome/URL bar if it reveals
`localhost` in a way that looks unpolished (optional — `localhost:5173` in
a dev screenshot is honest and not something to hide, just a style call).

## Image 3 — Architecture

**Purpose:** communicate, at a glance, that this is a properly layered
system, not a script.

**Suggested composition:** a simple vertical flow diagram, text-only, no
screenshot:
```
Frontend
   ↓
REST API
   ↓
External APIs
   ↓
Data Processing
```

**Notes:** this can reuse (visually restyled, not copy-pasted) the same
shape as the Architecture diagram in [`README.md`](../README.md) and
[`docs/CASE_STUDY.md`](./CASE_STUDY.md), so a buyer who looks at both the
Gig and the GitHub repo sees a consistent story.
